Stewardship — screen mockups

Static mockups of both halves of the application: the participant experience — getting in, the curriculum, a learning module, 1-on-1 sessions, and notes — and the administration screens on which that curriculum is authored, ordered, and published. Each file is self-contained — open it in a browser.

Curriculum copy is drawn from the starter programme. Session dates and times are sample values, and [BRACKETED] items are facts still to be filled in. Every file names the requirements it discharges, and the coverage table at the foot lists all sixty-four.

The twelve-module, twelve-week cohort shown throughout is a worked example, not a fixed shape. Every count, remainder, proportion, and allowance on these screens is derived from the authored programme and the cohort record — an eight-module programme and an eight-week cohort are drawn beside it so that nothing here can be read as a constant.

Four conventions worth knowing

A screen's alternate states stack as labelled artboards inside one file rather than one file per state, so shared chrome is written once. Module reading text and practice steps are never shortened at phone width — L2-015 requires them identical at every size; only editorial chrome is rewritten shorter. And state-legend.html is normative for marks, palette roles, focus, and target size.

The fourth is that every file describes one world: three programmes — the twelve-module Stewardship — core and the eight-module Redemptive practice intensive, both published, and a third still draft — and the three cohorts that follow them, one of which runs eight weeks and is allowed four sessions. A figure on an authoring screen can be checked against the participant screen that displays it.
